# Ralleh Flow Review — 2026-06-15

Scope: code review + architecture review + security/operational review of the active branch.

## 1) What is solid today

- API/runtime has real state transitions for `create -> pending -> running -> awaiting_approval -> resume/complete/fail`.
- Git isolation is implemented with branch naming + `git worktree add` and runtime run directories.
- Approval persistence and decision endpoints are implemented and exercised.
- Coordination supports memory and Redis modes with readiness behavior that reports truthfully.
- UI covers core operator surfaces; Playwright suite includes success + empty/error states.

## 2) Key findings

### High priority

1. **Request-body hardening gap in API JSON endpoints**
   - Previous behavior decoded unbounded request bodies and accepted unknown JSON fields.
   - Risk: memory abuse / contract drift from silent extra fields.

2. **Docs drift vs implementation**
   - `docs/development-plan.md` still listed several already-implemented features as missing.
   - `docs/architecture.md` implied execution breadth without clearly marking current MVP execution boundary.

### Medium priority

3. **Autonomous execution boundary still incomplete**
   - Orchestration transitions are present, but step-kind execution workers are still callback/operator-driven.

4. **Operational hardening still pending**
   - AuthN/AuthZ, artifact registry/upload APIs, retention/cleanup automation, and richer live streaming UI remain roadmap items.

## 3) Implemented in this pass

### A) API security/contract hardening

Updated `apps/api/internal/api/server.go`:
- Added 1 MiB JSON body limit (`http.MaxBytesReader`) for write endpoints.
- Added strict JSON decoding (`DisallowUnknownFields`) to reject unknown keys.
- Added single-object enforcement (reject trailing JSON payloads).
- Added consistent `413` response for oversized payloads.

### B) Regression coverage

Updated `apps/api/internal/api/server_test.go`:
- `TestCreateRunRejectsUnknownJSONFields`
- `TestCreateRunRejectsOversizedJSONBody`

### C) Documentation sync

Updated `docs/development-plan.md`:
- Replaced stale “not implemented” list with current implementation reality.
- Reframed active gaps to real near-term priorities.

Updated `docs/architecture.md`:
- Clarified current MVP execution boundary (state transitions/callbacks implemented; fully autonomous workers still targeted).

## 4) Recommended next hardening slice

1. Add authn/authz middleware for mutation endpoints (`POST /v1/*`).
2. Add rate limiting + structured audit logs for approval decisions and run mutation endpoints.
3. Implement run retention policy (archive + cleanup of worktrees/runtime dirs).
4. Introduce live events transport to UI (SSE/WebSocket) backed by event stream.
